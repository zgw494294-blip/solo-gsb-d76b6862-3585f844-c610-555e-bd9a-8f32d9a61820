# 🎭 舞台提示执行台

本地舞台提示（Cue）执行控制台。开场前按顺序录入 2～12 条提示，演出中逐条确认发出；
支持演出中改写、重排尚未发出的提示，已发记录保持原样。

## 启动

一条命令（需要 Docker 与 Docker Compose）：

```bash
docker compose up --build
```

启动后访问：**http://localhost:8000**（端口 **8000**）

数据保存在名为 `cue-data` 的 Docker 卷中（SQLite），刷新页面、重启服务均不丢失提示顺序与进度。

## 功能说明

- **录入**：开场前录入 2～12 条提示，每条需唯一编号 + 非空内容，顺序即发出顺序。
- **演出视图**：大字显示当前待发提示与下一条，侧栏为待发队列和已发记录（含发出时间）。
- **确认发出**：服务端把那一刻的内容快照记为已发并推进一条；全部发出后显示完成。
- **演出中修改**：可改写内容、上移/下移重排尚未发出的提示；已发记录不可变。
- **并发与防误触**：
  - 页面每次操作都携带当前看到的版本号，服务端校验，过期请求返回 409 并附带最新状态，页面自动刷新；
  - 同一版本的两个操作只有一个生效；
  - 确认按钮在请求进行中禁用，重复点击不会跳过提示；
  - 编辑胜出后版本号已变，基于旧内容的确认会被拒绝。

## 本地开发（不用 Docker）

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

同样访问 http://localhost:8000 。默认数据库文件为 `app/cues.db`，可用环境变量 `CUE_DB` 指定其他路径。

## 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 获取当前状态（版本号、阶段、当前/下一条、待发与已发列表） |
| POST | `/api/setup` | 录入提示并开场 `{cues: [{cue_id, content}, ...]}` |
| POST | `/api/confirm` | 确认发出当前提示 `{version}` |
| POST | `/api/edit` | 改写待发提示 `{version, cue_id, content}` |
| POST | `/api/reorder` | 重排待发队列 `{version, order: [cue_id, ...]}` |
| POST | `/api/reset` | 清空进度回到录入 `{version}` |
